  • Web-shell persistence: the group has deployed ASP and PHP web shells (publicly documented variants include the “RedHat Hacker” web-shell family) to maintain access after initial exploitation.
  • Watering-hole operations: Andariel’s SyncHole activity compromised legitimate South Korean websites to stage payloads.

VULNERABILITY ANALYSIS

PHP2SHELL · CVE-2026-109618 · CVE-2026-109619

PHP2Shell refers to two critical unauthenticated remote code execution vulnerabilities in the PHP runtime itself. Both carry a CVSS v4.0 score of 9.2 (PHP Security Team). Technical details leaked publicly on 20 October 2026, ahead of coordinated disclosure; the PHP project released fixes on 21 October 2026. Both share one root cause: PHP’s longjmp()-based “bailout” aborts a request mid-operation and leaves internal state half-built or pointing at freed memory. In worker-based deployments, a subsequent request handled by the same worker inherits that stale state.

CVE-2026-109618: RCE via out-of-memory corruption (GHSA-w8hw-w9fx-j79w)

  • When a request exceeds memory_limit, PHP bails out of the allocator; some execution contexts leave request memory partially initialised, and shutdown cleanup then reads or branches on it.
  • The attacker controls when memory is exhausted through the multipart parser.
  • Confirmed full unauthenticated RCE on Apache mod_php with default settings and prefork. Reported by Calif, Wiz, OpenAI and Quarkslab.

CVE-2026-109619: RCE via stale global state (GHSA-6wmf-4rv5-p3rp)

  • A request that dies at the wrong moment (fatal error, timeout or OOM) leaves request-owned global state pointing at freed memory; a later request on the same worker reads it before initialisation, a use-after-free.
  • Confirmed consumers: session upload progress (PHP_SESSION_UPLOAD_PROGRESS) and PHP 8.5’s fatal_error_backtraces. Validated against both mod_php and PHP-FPM.

INTERIM CONTROLS DIFFER BY CVE
Early coverage tied the session upload-progress field to CVE-2026-109618. Per PHP’s advisories it belongs to CVE-2026-109619 only; disabling upload progress does nothing for -109618. The two bugs require different interim controls (Section 08).

TEMPORARY CONTROLS DO NOT REPLACE PATCHING
