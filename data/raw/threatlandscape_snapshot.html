PHP2Shell Campaign: Korean-Speaking Operators Scan 216 Hosts for CVE-2026-109618 and CVE-2026-109619

TLT
Threat Landscape Team
2026-10-259 min read

Korean-speaking operators coordinating via a closed I2P channel have moved from reconnaissance to active, low-and-slow scanning of a filtered 216-host target set of internet-facing PHP systems. The activity targets CVE-2026-109618 and CVE-2026-109619 (PHP2Shell), two critical unauthenticated remote code execution flaws in the PHP runtime itself, each scored CVSS v4.0 9.2. Fixes for supported branches shipped on 21 October 2026. Earliest confirmed exploitation activity dates to 17 October. Organizations running PHP below the fixed versions should treat the exposure as immediate and prioritize patching, worker restarts, and hunting.

Vulnerability Overview

PHP2Shell refers to two related memory-safety defects in the PHP core that enable unauthenticated RCE independent of the application running on top of the runtime. Both flaws are triggered by crafted multipart/form-data requests processed before application code or authentication executes. Highest observed reliability occurs against Apache mod_php in the default prefork MPM.

  • CVE-2026-109618 (GHSA-w8hw-w9fx-j79w): Out-of-memory corruption via longjmp() bailout when memory_limit is exceeded during request startup. Cleanup treats partially initialized request-owned memory as valid, enabling use-after-free and subsequent control of execution flow.
  • CVE-2026-109619 (GHSA-6wmf-4rv5-p3rp): Stale global state (use-after-free) after a fatal error or interrupted request. Session upload progress handling (PHP_SESSION_UPLOAD_PROGRESS) is a primary path; the next request handled by the same worker reuses freed memory containing attacker-controlled data.

Affected versions include PHP 8.2.x before 8.2.35, 8.3.x before 8.3.36, 8.4.x before 8.4.27, and 8.5.x before 8.5.12. Older branches (8.1 and earlier) receive no official upstream fix. Public proof-of-concept tooling is circulating; multiple vendors observed scanning and early exploitation attempts before and immediately after the 21 October patch release. Successful exploitation yields code execution in the context of the web server process, enabling web shell deployment, credential access, and further lateral movement.

Campaign Analysis and TTPs

CYFIRMA collection of the closed I2P channel identified two Korean-speaking handles active since March 2026. The operators rank public proof-of-concept code with a local AI model, perform lab validation, and maintain infrastructure separation between staging hosts and compromised scan nodes. Tradecraft emphasizes low-and-slow pacing, node rotation, and burn discipline against filtered or rate-limited targets to avoid noisy sweeps.

On 24 October 2026 the operators reported a 216-host target set of unpatched or partially mitigated systems ready for scanning. Approximately one-third of the set had already been checked. Scan nodes were observed performing PHP web shell tooling and upload-progress session poisoning. No launch date or mass compromise has been observed. Confidence in campaign activity is high; linkage to the Lazarus Group ecosystem (APT38, Hidden Cobra, ZINC, Diamond Sleet) remains moderate, based on language, sector prioritization, geographic targeting patterns, and historical web-shell tradecraft. Infrastructure and malware overlap has not yet been confirmed.

Primary objectives appear dual-use: financial (initial-access resale, cryptocurrency theft, ransomware) and espionage against government and financial institutions. The operators filtered out hosts advertising fixed versions or heavy filtering, leaving systems that still advertise older PHP versions.

Target Profile and Risk

The 216-host set spans prioritized sectors and geographies. Tier-1 targets are government entities and banking/financial services institutions. Tier-2 includes manufacturing, logistics, shipping, airports, and aviation. Tier-3 covers online transaction platforms, trading firms, and construction. Geographies explicitly discussed include the United States, Japan, Thailand, Indonesia, South Korea, Australia, Taiwan, India, Singapore, the United Arab Emirates, Saudi Arabia, and the European Union.

Any organization running internet-facing PHP below the fixed versions should assume it may be in scope or will be added as scanning continues. Shared hosting, control panels (cPanel, Plesk), appliances embedding PHP, and environments using Apache mod_php face elevated risk. Reloads without full worker restarts leave stale process state that preserves the vulnerability window.

Mitigations and Hunting Guidance

Immediate actions:

  • Patch all supported PHP instances to 8.5.12, 8.4.27, 8.3.36, or 8.2.35 and restart every worker process. Reloads leave vulnerable state.
  • For unpatchable hosts (especially Apache mod_php and EOL branches), isolate from the internet or apply the following temporary controls and restart workers:
    • session.upload_progress.enabled = 0
    • fatal_error_backtraces = 0 (PHP 8.5)
    • memory_limit = -1 (administrative enforcement only; removes resource protection)
    • Constrain post_max_size, multipart part counts, and max_input_nesting_level
    • Set pm.max_requests = 1 where feasible to shorten worker lifetime
  • Block or closely monitor the scan-node, Version 2 source, and staging addresses listed in the Indicators section at perimeter and host firewalls.
  • Hunt logs back to 17 October 2026 for low-volume multipart/form-data anomalies, worker crashes, unexpected session file modifications, and the user-agents and canary strings listed below.
  • Preserve evidence (memory dumps, session files, request captures) before patching or restarting; restarts destroy CVE-2026-109619 state.
